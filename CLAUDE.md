# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Z-Color-Picker is a single-binary Rust (edition 2021) desktop app built on `eframe`/`egui` 0.31 + `egui_tiles`. The user places control points on a 2D saturation/value (or lightness, chroma, a/b) picker plus a hue (Oklab: lightness) bar, in a selectable picker space (HSV, HSL, OKHSV, OKHSL, OkLCh, Oklab), and the app interpolates a color gradient through them using a selectable spline mode, in a selectable blend space (the picker space, sRGB, Linear RGB, Oklab, OkLCh). A 3D pane draws that gradient curve in a color space, where points and Bezier handles can be dragged too. Presets can be saved and loaded, and gradients or colors can be copied to the clipboard.

## Commands

```
cargo build
cargo run            # run from repo root: presets resolve relative to the CWD
cargo clippy         # exits 0; warn-level style lints remain
cargo test
cargo test hermite   # single test by name filter (bin crate; tests live in #[cfg(test)] modules under src/)
```

- The build is warning-free. Keep it that way: delete unused code, no `#[allow]`.
- No third-party code: never copy, port or paraphrase code from crate sources, egui demos or articles. Published math and constants are fine; write the code in this codebase's style. Depending on a crate is fine.
- Every `src` module has a `#[cfg(test)] mod tests`, except `debug_windows.rs` and the `mod` files. `preset.rs` tests use tempfile dirs, never `./presets`. Shared fixtures live in `#[cfg(test)] pub mod test_support` in `control_point.rs` (`point_with_tangent`, the runaway-tangent constants) and `hsv_key_value.rs` (`assert_close`). Widget tests run a headless `egui::Context::run`; the rest of the UI is checked by running the app.
- Line endings differ from file to file (some CRLF, some LF). Keep each file's existing endings.
- `.vscode/launch.json` has lldb (CodeLLDB) configs for the binary and its unit tests.

## Controls (from README)
- Double-click (M1) on the picker: add a control point.
- Right-click (M2) on a point: remove it.
- Click the color readout or Ctrl+C: copy the selected point's color in the Copy-as format.
- Click a Hex, sRGB, HSL, Oklab or OkLCh row (under the inspector): copy the selected point's color in that row's format.
- Middle-click: copy the color under the cursor in the selected format. On the previewer, it copies the image instead.
- Drag (M1): move a point, a Bezier tangent handle, a hue gizmo, or a middle point's T (its marker on the T strip, or its previewer key band). End T markers and bands are fixed; clicking a marker selects its point.
- Inspector (H, S, V or L, T under the readout): drag, or click and type the selected point's value; Enter, Tab or a click away commits, Esc cancels.
- Click the log drawer's header (or the toolbar Log toggle): expand or collapse the log.
- 3D view: drag (M1) on a point, or in Bezier mode on a handle of the selected point, moves it; elsewhere it orbits. With Lock a point drag moves every point's S/V like the square (Window lock stops it at the edge), and z only the dragged point's. Under Auto hue a middle point keeps its hue and its S/V follow the pointer as near as that hue allows. Click a point: select it. Scroll zooms, double-click off the points and handles resets the camera; hovering a point, handle or the curve shows its hex color.
- F12: debug window with the control point values.
- Esc: quit, only on a first press (not a key repeat) and only when `ZApp::is_input_blocked` is false: no widget had keyboard focus last frame, and no popup, modal (delete confirm, pending switch) or Create Preset window is open. It is read before the tree is drawn, because egui drops focus and closes popups during the Esc frame. The same flag blocks Ctrl+C (`should_quit_on_escape`, `is_copy_shortcut`).

## Architecture

### App state and ownership
- `src/main.rs` starts eframe. If eframe persistence storage holds a serialized `ZApp` (JSON under `eframe::APP_KEY`), the app is deserialized from it and `request_init()` sends it back through the startup path. Otherwise `ZApp::new` is used.
- `ZApp` (`src/ui_egui/app.rs`) is a small state machine (`Startup` -> `Idle` -> `Exit`). It owns the `egui_tiles::Tree<Pane>` and an `Rc<RefCell<ZColorPickerAppContext>>`.
- `ZColorPickerAppContext` is the central mutable state: `control_points`, `spline_mode`, `PresetHandler`, the picker and previewer widgets, pending input events, and so on. Each pane (`src/ui_egui/panes.rs`: ColorPicker, Previewer, View3d) holds a clone of that `Rc`. After deserialization, `startup()` walks the tile tree and calls `update_ctx` to re-point every pane at the live context. Serde does not preserve `Rc` sharing, so this step is load-bearing.
- Because everything shares one `RefCell`, borrow conflicts are the main runtime hazard. The existing code clones data out, drops the borrow, draws, then re-borrows mutably to write back. Examples are the `ui()` methods in `panes.rs` and `show_create_preset_window`. Follow that pattern.
- Any cloned state has to be written back explicitly, or the edits are lost without any error. For example, `preset_bar_ui` has to assign `presets_window` and `preset_handler` back to the context.
- The layout (`create_tree`) is the picker column on the left (one ColorPicker pane: the picker plus the Points, Curve and Comb option rows), and on the right the 3D view over the previewer (55/45). The toolbar (`ZApp::draw_toolbar`, a `TopBottomPanel` drawn before the tile tree) holds, left to right, the preset bar (`WindowPreset` via `preset_bar_ui` in `panes.rs`), the Copy-as combo and the Log toggle at the right end, each group under a section header and between `theme::group_separator`s. The option rows are free functions in `content_windows.rs` (`picker_space_combo`, `points_row`, `curve_row`: Spline, Blend, Flip, `comb_row`); there is no options pane.
- The picker pane keeps its minimum size. `picker_ui` sets `ZColorPickerWrapper::min_size` (`picker_min_size`: in height the `MIN_SQUARE_SIDE` square and strips plus `stack_fixed_height`; in width the wider of that square and the non-wrapping rows, the header's Space row and the inspector, measured in the previous pass). egui_tiles 0.12 has no per-tile minimum (`Behavior::min_size` is one value for all tiles, used only while dragging a splitter), so `ZApp::draw_tree` raises the picker's share in its parent `Linear` to that size plus the card padding for the frame (`ShareFloor`), then puts the user's shares back, so a small window doesn't widen the picker for good; a splitter drag that frame is kept, floored. When the pane is still smaller (the window is), `draw_ui` scrolls on that axis in a `ScrollArea` clipped to the pane; an axis that fits doesn't scroll, since egui's 1/32 point rounding overflows an exact fit. A label and its widget in a wrapping option row go through `theme::unbroken_group`, which allocates them at their last laid-out width: a nested `ui.horizontal` in a wrapping row overflows instead of moving to the next line. The "Create Preset" window is drawn from `ZApp::draw_ui_tree` before the toolbar. Rename is a `popup_below_widget` popup, not a `menu_button`: egui menus are not `Memory` popups, so `any_popup_open` would miss them and Esc would also quit.
- The log is a bottom drawer, not a tile: `ZApp::draw_log_drawer`, a `TopBottomPanel` drawn after the toolbar and before the tile tree. Its header (`ui_log_header` in `src/logger.rs`: painted chevron, "Log", and the last line while collapsed) and the toolbar Log toggle flip the same persisted `ZApp::is_log_expanded` (serde default: collapsed). Collapsed and expanded are two panels with their own ids, so the collapsed one never starts from the expanded height in egui's panel memory. The expanded height the user chose is the persisted `ZApp::log_drawer_height` (serde default `LOG_DRAWER_DEFAULT_HEIGHT`). egui's resizing is off: the panel is shown at `exact_height` (egui's own panel memory is ignored), the stored height clamped to `LOG_DRAWER_MIN_HEIGHT` and the cap `log_drawer_max_height`, which leaves the tile area the picker tile's minimum height (`picker_tile_min_size`, from the previous pass) plus the central panel's margins; in a window too small for both it goes down to its header only, below its drag minimum, before the tiles shrink. Only the drag on the drawer's own top-edge grab (`log_drawer_grab`, its response read before the panel is laid out, so no frame of lag) writes the stored height, clamped to that range; the cap never does, so a short window can't shrink it for good and a taller one gives it back.
- `ZApp::layout_version` (serde default 0) versions the saved tile tree. When the restored version is below `LAYOUT_VERSION`, `startup` (`upgrade_layout`) replaces the tree with `create_tree` before re-pointing the panes; pane state lives in the shared context, so only divider positions and the 3D camera reset. Bump `LAYOUT_VERSION` whenever `create_tree` changes shape. Old trees still have to parse: their Log and options tiles parse into the empty `LogPane` and `ColorPickerOptionsPane` (fixture: `src/ui_egui/testdata/old_layout_app.json`).
- Fields marked `#[serde(skip)]` are transient UI/event state. Anything without it is persisted in eframe storage, so changing a persisted type's shape can break loading of existing saved state. On a parse failure, loading logs a warning (`Ignoring stored app state`) and falls back to defaults.

### Data model
- `ControlPoint` (`src/datatypes/control_point.rs`) is an enum over `ControlPointStorage { val, t, tangents: [Option<_>; 2], curvature: Option<f32> }` (curvature: Auto comb's per-point curvature).
- `ControlPointValue` = `HsvKeyValue` (`src/datatypes/hsv_key_value.rs`), which stores `[f32; 3]`. The index order is **`[s (x), v (y), h]`, not `[h, s, v]`**: index 0/1 are the 2D picker position and index 2 is hue, except in Oklab, where it is lightness. In the HSL spaces and OkLCh y is lightness (see Color spaces). `HsvKeyValue` implements `splines::Interpolate`, with hue-aware lerp from `src/math.rs`.
- Tangents are stored as offsets relative to the point's value. Bezier keys, the ribbon, the comb and the drawn handles all use `bezier_handle` (point + offset with S/V clamped to the square, hue not), so a stored runaway tangent cannot wreck the curve.

### Spline evaluation
- `control_points_to_spline` (`src/ui_egui/control_points.rs`) converts control points into a `splines::Spline`, one match arm per `SplineMode` (`src/common.rs`). `SplineMode::ALL` feeds the Spline combo and the per-mode tests; a new mode goes there too.
- Keys are placed at `ControlPoint.t` ("T", the position along the gradient). Invariant (`has_valid_t`): first T = 0, last T = 1 (a single point has 0), strictly increasing by index, so index order is T order. `normalize_t` spaces invalid T evenly; it runs in `pre_draw_update` and `apply_control_point_constraints`, on preset load (`load_preset_from_disk`, in memory only) and on restored eframe state (`ZApp::init`, before `hold_auto_save_if_dirty`, so old data doesn't look dirty), each with a `log::warn`. `control_points_to_spline` keys invalid T evenly too (`key_ts`).
- Every T edit keeps the invariant, in `control_points.rs`: `insert_point` (between two points: the middle of their T; at an end: the new point is pinned and the others are squeezed by 1/old count), `remove_point` (removing an end rescales the rest onto 0..1), `mirror_t` (Flip), `drag_t` (middle points only, `MIN_T_GAP` from both neighbours). Auto hue interpolates middle hues by T.
- `HermiteBezier` is actually Catmull-Rom with a parabolic end condition: a phantom key sits one neighbour spacing outside each end key, valued by the parabola through the three end keys at their T, extrapolated (`polynomial_through`, on unwrapped hue). Two keys give a straight segment, one key is duplicated. A duplicated end key would put an inflection in each end segment of a C shape, flipping the comb. Its tangents follow the T spacing (non-uniform Catmull-Rom in `HsvKeyValue::cubic_hermite`).
- There is no `Polynomial` mode; saved JSON that names it fails to parse.
- `flatten_control_points` unwraps hue across the 0/1 boundary before interpolation. Oklab skips it (see `Gradient`).
- `sample_spline_normalized` maps x in [0,1] onto the real keys (`real_keys` drops the Catmull-Rom phantoms), so x = T. It handles the end of a Catmull-Rom spline, where the `splines` sampler returns `None`. The ribbon (`generate_spline_points`) samples a fixed count per real segment between key T.
- `Gradient` (`src/ui_egui/blend.rs`) is the one sampling entry point for every gradient consumer: the T strip (`gradient_color_at`), the previewer gradient and quantized strip, the ribbon and the 3D view. Build it once per draw, then call `color_at` / `linear_at` / `picker_value_at` with x in [0,1]; nothing allocates per sample. `BlendSpace::Picker` (default) is the spline over the flattened picker values, bit for bit the old path; in Oklab, where z is lightness, it is a componentwise `BlendValue` spline over the raw values and handles (`PickerComponentwise`), so L moves straight instead of wrapping. sRGB, Linear RGB, Oklab and OkLCh convert each value and each Bezier handle (`bezier_handle`) through linear sRGB into a componentwise `BlendValue` spline with the same key T, mode and phantoms (`spline_through_keys`), and convert samples back. A sample outside sRGB goes through `map_into_srgb_gamut` (`color_space.rs`): its OkLCh chroma is bisected down at its L (clamped to [0, 1]) and hue, so a per-channel clip no longer shifts its hue and lightness; in-gamut colors pass bit for bit. Within ~0.15 deg of hue past sRGB blue a chroma ray leaves sRGB and re-enters (a thin fin out to blue), so the bisection can stop at the inner edge, a few percent of chroma short; it stays deterministic and `clipped_to_srgb` idempotent. In HSV, HSL, OKHSV and OKHSL the sRGB boundary is the square's s = 1 edge (and v = 1 in HSV, OKHSV), so mapped samples still sit on that edge; the gain is the kept hue and lightness. In OkLCh and Oklab it runs inside the square. The ribbon draws `linear_to_picker` of the mapped color, S/Y clamped against float noise. OkLCh unwraps hue across keys (short arc), an achromatic key takes the previous (else next) chromatic key's hue, and negative chroma reads as 0.
- The previewer (`src/ui_egui/previewer.rs`) gradient, quantized strip and key color bands all follow T, as does the picker's T strip gradient (`gradient_color_at`). Key color bands split halfway between neighbouring T (`key_band_edges`). The previewer edits its own copy of the points (band drag, Space evenly), and `PreviewerPane::ui` writes it back to the context when it changed.
- Curvature comb drawing lives in `src/ui_egui/curvature.rs` and has its own cubic evaluation. It is toggled via `ZColorPickerOptions::is_show_curvature_comb`; `curvature_comb_scale` multiplies every spike's length. Linear has no comb. Hermite segments are converted from the spline's Catmull-Rom keys to exact cubic Beziers (`catmull_rom_cubics`, the tangent formula of `HsvKeyValue::cubic_hermite`), so they follow the key times. Hermite tangents are not drawn: the picker shows tangent handles only in Bezier mode. The comb and Auto comb measure picker geometry, so any blend but Picker turns both off (`comb_controls_enabled`, `ZColorPickerWrapper::draw_ui`, `pre_draw_update`).
- Auto comb (`ZColorPickerOptions::is_auto_comb`, Bezier only) runs `apply_auto_comb` (`src/ui_egui/auto_comb.rs`) in `ZColorPickerWrapper::pre_draw_update`, after the constraints, so a later clamp can't move solved points. In S/V, with the handle directions held (an interior point's two handles lined up), it solves every handle length of the chain at once, in log length (`Chain`): G2 at each interior joint is a hard constraint (the endpoint-curvature formula of https://acko.net/blog/curvature-beziers/), each point's stored signed curvature (`ControlPointStorage::curvature`, serde-skipped when `None`) is a soft target, and each length is softly held at its current value. The solve is bounded Levenberg-Marquardt: the G2 gaps enter as a penalty of rising weight (`GAP_WEIGHTS`; the stages before the last only warm-start it), then a last solve closes them alone. A stage ends once no step would move a log length by more than its tolerance (`STEP_TOLERANCE`, coarse `WARM_START_STEP_TOLERANCE` for the warm-start stages), and a variable that the gradient or the step pushes out through its bound is held for that step. A residual touches only the lengths of a joint's two segments, so each step is a band Cholesky (`solve_band`), linear in the point count. Lengths stay between `MIN_SOLVED_LENGTH` and the square's edge. After a solve the achieved curvatures are stored as the targets, so intent follows the solution. Missing curvatures are seeded from the handles (the circle through the neighbours where they are degenerate or the two sides disagree); enabling Auto comb (`was_auto_comb_running`) and applying a preset (`normalize_applied_preset` clears it, so the pass is in memory only) reseed those the handles no longer meet. `CombEdit` weights the frame's drag: the dragged point's target is weak, a dragged handle's point target and its length are strong. Handle drags go through `drag_handle_by` (the square's; the 3D view's through `drag_handle_to`, which takes the handle's position; the caller sets `dragging_tangent`): the drag along the handle sets its point's target (the curvature of stretching it along its old direction, the rest held), the next pass turns the joint to the handle's new direction. A joint that can't reach G2 inside the length bounds freezes both its segments, which keep their lengths and count in `N unsolved`: `freeze_infeasible_joints` propagates exact curvature ranges along the chain (`Segment::end_range` / `start_range`, with G2 at every other joint), so a chain whose directions can't meet is found without solving, and the same frozen set comes back every frame; where a solve still leaves gaps open (a local minimum), each gap that is the widest within `OPEN_JOINT_WINDOW` joints freezes at once (`Chain::open_joints`). Runs of free segments between frozen ones share no variable and are settled or solved on their own (`settle_runs`), so a settled run costs no solve. `SOLVER_ITERATIONS` (test only) counts Levenberg-Marquardt iterations for the iteration-bound test. Solved handles stay inside the square; tangent hue offsets are untouched. Flip negates the curvatures, a picker-space switch clears them. The result must be a fixed point (another pass changes nothing, bit for bit), or auto-save rewrites the preset every frame: a run whose handles already meet G2 and the targets within `CURVATURE_TOLERANCE` plus f32 rounding slack (`Chain::is_settled`) only stores missing seeds, and moves below f32 resolution are dropped. Stored in f32, G2 at a short handle holds only to its rounding slack, which grows as 1/length^3.

### Presets
- `src/preset.rs`: one JSON file per `PresetEntity` in `./presets/` (the `presets/` folder is gitignored). The path comes from `std::env::current_dir()`.
- Presets are written through to disk: Create, Save, Rename and Delete in the preset bar (`WindowPreset::draw_content`, `ZApp::show_create_preset_window`) hit disk immediately via `PresetHandler`. Nothing is synced at exit.
- Every write goes to `<name>.json.tmp` and is renamed over the file (`fs::write_string_to_file`). Create and Rename refuse a name whose file already exists on disk (`ensure_no_preset_file`), even if it is not in the list; Rename allows a case-only change. Create writes the file, then adds it to the list. Rename uses `fs::rename`. Both re-sort the list in load order (`sort_presets`) and keep the selection on its preset. Delete removes the file first, behind a confirm `Modal`; a file that is already gone counts as deleted.
- Name rules, enforced by `validate_preset_name` / `PresetHandler::check_name`: not empty or whitespace; no `< > : " / \ | ? *` or control chars; no trailing dot or space; no reserved device name (CON, NUL, COM1..); at most 64 chars; no case-insensitive duplicate. The UI disables Create/Rename and shows the reason in red.
- When `auto_save_presets` is enabled, the selected preset is rewritten only when the current control points, spline mode, picker space or blend space differ from it (`PresetHandler::auto_save`), and only once no pointer button is held, so a drag writes once, on release. A failed write keeps the preset dirty, shows the error in the preset bar, and is not retried until the content changes again.
- `PresetHandler.presets` is `#[serde(skip)]`: presets are not in eframe storage, disk is the truth. At startup `init_presets` loads them from `presets_dir` (default `./presets`), skips non-`.json`, malformed or non-finite files (`first_non_finite_point`) with `log::warn`, and sorts them by name, case-insensitive. Only the selected preset's name is persisted (`selected_preset`); it is restored by case-insensitive name, else `None`. If the restored points differ from that file, `hold_auto_save_if_dirty` marks them as a held auto-save, so Auto-save does not overwrite the file until the next edit. `ZApp::init` runs the picker's `pre_draw_update` (Bezier tangents, auto comb) before that check, so the first frame's pass counts as restored, not as an edit.
- Unsaved changes (`has_unsaved_changes`: the selection is dirty and Auto-save is off or its last write failed) show as `name *` in the combo. Picking a preset then, or while unselected points match no preset, sets `WindowPreset::pending_switch` and opens a modal instead of applying it: Save and switch / Discard / Cancel; for the already selected preset Save / Revert to saved / Cancel; with no selection Discard / Cancel. A failed save keeps the modal open with the error. Applying a preset clears the point selection.
- Save without a selection opens the Create Preset window.

### Color spaces
- `src/color_space.rs` holds flat conversions on `[f32; 3]` with linear sRGB as the hub: `srgb_to_linear` / `linear_to_srgb` (gamma sRGB, via ecolor), `linear_to_oklab` / `oklab_to_linear` and `oklab_to_oklch` (Ottosson's matrices, rounded to f32), `srgb_to_hsl`, `srgb_to_hsv` (standard HSV of the sRGB bytes, not the picker's `HsvaGamma`). Hue is in turns [0, 1) like the app's hue, `[h, s, l]` and `[l, c, h]` order; chroma below `ACHROMATIC_CHROMA` gets hue 0.
- `PickerSpace` (Hsv default, Hsl, Okhsv, Okhsl, Oklch, Oklab) says what a point's x/y/z mean; `picker_to_linear` / `linear_to_picker` convert `[z, x, y]` (`[h, s, v|l]`). OkLCh is x = chroma / `OK_SQUARE_CHROMA` (0.33, past sRGB's largest, 0.3225), y = L, z = hue; Oklab is a and b mapped from +-0.33 onto x and y (gray at 0.5, 0.5), z = L. `is_z_hue` (false only for Oklab) gates everything that treats z as a hue: `z_on_bar` wraps a hue but clamps L, the hue lerp and `flatten_control_points`, `hue_after_drag`, Auto hue (`ZColorPickerOptions::is_auto_hue`; the checkbox is disabled), Clamp, the bar (an L bar through the selected point's a/b; OkLCh's hue bar sits at `OKLCH_HUE_BAR_XY`, inside sRGB at every hue), the inspector (L, a, b), tangent offsets in `convert_picker_space` and the 3D view's moves (`picker_value_from_linear`). `HsvKeyValue::color(space)` / `linear(space)` (S/V clamped, z on the bar, then `map_into_srgb_gamut`) is the only point or spline sample -> color path; the square, hue bar (s 1 at v 1, or l 0.5), T strip, ribbon, previewer, swatch, readout rows, copy and the 3D view's points all go through it. `unmapped_linear` is the same without the gamut map, for the in-gamut test (`is_in_srgb`) and OkLCh <-> Oklab switches. `linear_to_color32` is the one linear -> `Color32` step. A gray in any hue space reads back with s and h exactly 0 (OkLCh zeroes chroma below `ACHROMATIC_CHROMA`). Okhsl l up to `OKHSL_BLACK_L` (1e-6) is black, because below it `rounded_chroma`'s c^-4 overflows f32 into NaN; `value_in_picker_space` asserts that conversions stay finite.
- Hsv is ecolor's `HsvaGamma` (HSV over linear RGB with only V gamma-encoded, not CSS HSV), bit for bit; Hsl is CSS HSL over gamma sRGB. Okhsv/Okhsl are our own code for Ottosson's two spaces, with his published constants (toe k1..k3, the fits in `CHANNEL_REGION_FITS`, `BLUE_CHANNEL_FIT`, `MID_BLACK_SLOPE`, `MID_WHITE_SLOPE`). `HuePlane` is one hue: `black_edge_slope` (a fit refined by Halley steps), `cusp`, `max_chroma` (one Halley step above the cusp). Okhsv's v = 1 edge is the triangle's white edge (`okhsv_edge`, `okhsv_top_scale`); Okhsl maps s to chroma through two rational `Ramp`s (`OkhslChromas`). `black_edge_slope` tests green's region before red's, with a `BRANCH_TIE` margin, and takes 3 Halley steps: at sRGB blue both region tests are 1, a strict f32 test picks blue's fit, and red's finds a zero short of blue. With that, the primaries have s 1 (and OKHSV v 1). `okhsv_and_okhsl_reproduce_recorded_values_*` pin earlier outputs to 1e-5; Okhsl s near white is left out, since a 1-ulp input change moves it by up to ~1e-4 there.
- The space is persisted in `ZColorPickerAppContext.picker_space`, `AppDataCtx` (preset files) and `PreviewerData`, all `#[serde(default)]`, so older state and presets load as Hsv. The preset dirty check (`data_matches`) compares it; applying a preset applies its space. The Space combo (picker header, under the readout) changes it, and `picker_header` then runs `convert_picker_space` once: each value and each Bezier handle (absolute, as `bezier_handle` builds it) goes through linear sRGB, gamut-mapped unless the new space is OkLCh or Oklab, which keep colors outside sRGB; hue offsets keep their turns; a gray keeps its old hue between hue spaces. Float noise can move an 8-bit channel that sits on a rounding boundary (V 50%, 70%: x.5 / 255) by 1. Auto hue then re-interpolates middle hues in the new space, so middle colors change with it on.
- Clip to sRGB (the Clip checkbox beside Space, `clip_to_srgb_checkbox`) lives in the variants, `Oklch { clip_to_srgb }` / `Oklab { clip_to_srgb }` (serde default false; old names still load as strings), so it is persisted, compared by `data_matches` and applied with the space everywhere the space goes; `is_same_space` ignores it, and the Space combo carries it between OkLCh and Oklab. On, `picker_cell_color` draws square and bar cells outside sRGB as `Color32::TRANSPARENT` (the panel shows through), and every edit runs `clip_points_to_srgb` on the points it moved: square drag (all points under Lock), bar click/drag, bar gizmo drag, inspector entry, double-click spawn, a 3D point drag (`move_point_to`, all points under Lock), and `convert_picker_space` (a space switch, or turning Clip on: once, over every point and handle). `HsvKeyValue::clipped_to_srgb` clamps x, y (and Oklab L) into the square, then bisects (`largest_scale_in_srgb`, shared with `map_into_srgb_gamut`) the point toward its gray, (0, y) or (0.5, 0.5), keeping L and hue bit for bit; a point inside sRGB comes back bit for bit, and a clipped point clips to itself. A Lock group move (square, inspector S/V, 3D) is limited before that, so it keeps its shape and slides along the edge: `srgb_move_fraction` bisects the fraction of the move (`largest_fraction_where`) at which every point the clip leaves unchanged still is, and `srgb_slide_fractions` then moves the rest one axis at a time (x, y, the 3D drag's z; two rounds), each limited the same way (`limit_group_delta_to_srgb` for an S/V delta; the 3D one also moves the dragged point's z); a point already outside is clipped as before. Bar drags (gizmo and background) and inspector drags (H, unlocked S/V) rebuild the value each frame from the one at drag start (egui temp data `drag_start`) instead of the clipped one, so a hue dragged out of sRGB and back gets its chroma back bit for bit; a square point drag is absolute already, and 3D targets are gamut-mapped by `linear_at`. Bezier handles: a 3D handle drag clips the handle's position (`clip_value_to_srgb`) before `drag_handle_to`, a square one its offset (`clamped_handle_offset`: into the square, then clipped; the offset is kept bit for bit when neither changes it) before `drag_handle_by`, and `convert_picker_space` runs `clip_handles_to_srgb` (`bezier_handle` clipped, offset stored again only if it changed). A square handle drag is absolute like a point drag: drag start stores the handle's offset (the drawn one when the min length or the square moved it) and the press origin (temp data `drag_start` on the handle's id, so per point and side), and each frame sets start offset + pointer delta, so a handle dragged along the gamut or square edge and back returns bit for bit. Never per frame: Auto hue can still move a middle point outside sRGB, a point move takes its handles along, Auto comb sets handle lengths, and all of those show gamut-mapped.
- `BlendSpace` (Picker default, Srgb, LinearRgb, Oklab, Oklch) is the space the gradient is interpolated in (`linear_to_blend` / `blend_to_linear`; Picker has no linear form and never reaches them). It is persisted like the picker space (`ZColorPickerAppContext.blend_space`, `AppDataCtx`, `PreviewerData`, serde default Picker), compared by `data_matches` and applied with a preset. The Blend combo sits after Spline in the picker's Curve row; switching converts nothing.

### Clipboard / screen capture
Pressing the middle button stores a `ScreenshotTarget` in `pending_screenshot_target` and requests one `ViewportCommand::Screenshot`. It closes the copy popup first, because eframe captures the frame painted in that same update. The target is the previewer rect under the cursor (rects come from `stored_ui_responses`), or else the pixel under the cursor. The screenshot event arrives in a later frame. `handle_screenshot_event` crops it with `crop_screenshot` (`src/ui_egui/clipboard.rs`) and turns it into a `ClipboardCopyEvent`. A pixel target takes the physical pixel at `floor(cursor * ppp)`, clamped to the screenshot; a previewer crop rounds both edges, so it takes the pixels whose centres lie inside the rect, clamped too. That event is consumed at the start of the next `Idle` frame (`handle_clipboardcopy_event`). Nothing in the app requests that frame: egui repaints right after any pass whose input has events, and the Screenshot event counts. A single pixel is copied as text in `color_copy_format`; a larger region is copied as an image via `arboard`. A failed write shows `Copy failed: <error>` in the popup.
- `format_color_as` supports all 14 `ColorStringCopy` formats, from unmultiplied sRGB; `Rgb`/`Rgba` are linear. The variants keep their old all-caps names as serde names (saved state and presets) and as UI text (`label`). `Hsl`/`Oklab`/`Oklch` are CSS Color 4 strings without alpha, with the fewest decimals that map every 8-bit color back to itself (checked over all 16.7M); `css_number` trims trailing zeros.
- A readout click or Ctrl+C skips the screenshot: `selected_color_payload` formats the selected point and `write_payload_to_clipboard` (shared with middle-click) writes it. Ctrl+C is left to egui while input is blocked (`is_input_blocked`, see Controls) or label text is selected.
- A readout row click takes the same path: `copy_request` is `(anchor, format)`, the Copy-as format for the readout and Ctrl+C, the row's own (`ReadoutRow::copy_format`) for a row.

### Picker layout and inspector
- The square and the hue bar are `color_field` and `color_strip` (`src/ui_egui/ui_common.rs`), both drawn from a `color_at` closure. `color_field` only paints and senses clicks; a cell with blank (alpha 0) and colored corners is painted again as an 8x8 sub-grid in a second mesh, so the Clip edge fades over 1/256 of the square instead of a 1/32 cell; `color_strip` is `color_function_gradient` with an outline and returns the pointer's x fraction (0..1, clamped) while pressed. `swatch` / `paint_swatch` draw checkers behind a non-opaque color, and `black_or_white_against` (relative luminance below 0.5: white) colors the point outlines, gizmos and ribbon halo. Picker-to-screen mapping is `unit_to_screen` / `screen_to_unit` (`control_points.rs`, y down).
- `column_fixed_height` hand-counts `main_color_picker`'s stack: the header (`picker_header`: swatch beside the readout and Space rows, `header_height`), inspector, color readout, hue strip, T strip, square, overlay spacing; `stack_fixed_height` adds the Points, Curve and Comb rows' height as laid out in the previous pass (egui temp data, like the fixed rows' width; a change calls `request_discard`); `picker_side` divides the rest between the square and the two strips. A new row must update it; `picker_insets_square_in_height_limited_pane` fails otherwise (it checks that the stack ends within 1 point of the pane bottom), and `picker_fits_its_min_size_with_nothing_clipped` checks the minimum. `PickerUiLayout::new` computes the column and the option rows' rect under it before anything is drawn: in a pane wider than the column needs, the column is centered as far as the fixed rows still fit; the rows span the pane, inset like a width-limited square, so their wrapping depends on the pane width alone, not on the square, and the measurement cannot oscillate. The rows' top comes from `column_fixed_height`, so a miscount also overlaps them (`picker_ui` has a `debug_assert` on the gap).
- The picker edits the options, the space and the curve directly: `MainColorPickerCtx` holds `&mut ZColorPickerOptions` (read through it for Lock, Clamp, Auto hue and the comb), `&mut PickerSpace`, `&mut SplineMode` and `&mut BlendSpace`; `picker_header` runs `convert_picker_space` in the frame the Space combo changes, so everything below it draws in the new space. `draw_ui` draws the option rows first, into their reserved rect (`option_rows_ui`), and runs `pre_draw_update` between the Curve and Comb rows, so a Points, Spline or Blend change or a Flip reaches the strips, the square and the `N unsolved` label in the same frame (Bezier tangents and Auto comb included); Flip reverses the points in place and ends a drag. `ColorPickerPane::ui` writes the space, spline mode and blend space back.
- The point inspector (`src/ui_egui/inspector.rs`) edits `MainColorPickerCtx.control_points`, the clone that `ColorPickerPane::ui` writes back after `post_draw` applies the constraints; it never touches the app context. Each DragValue edits a local copy and writes only on `changed()`, with `clamp_existing_to_range(false)` and `update_while_editing(false)`: drawing never rewrites a point (auto-save compares bit for bit), and typing commits once instead of per keystroke. The row's id includes the selected index, because a DragValue applies its pending text on focus loss to whatever value it is bound to. S/V under Lock go through `limit_group_delta` / `apply_group_delta_sv` like a square drag, T through `drag_t` / `t_drag_bounds`, H keeps the turn like `hue_after_drag` (Oklab: L clamped to 0..1). Each field's `FieldUnit` maps the stored value to what it shows and back, for the value, the range, typed text and the drag speed (kept per stored unit): degrees, % of the square (HSV, HSL, OKHSV, OKHSL), or absolute OkLCh/Oklab values with fixed 3 decimals (L 0..1, C 0..`OK_SQUARE_CHROMA`, a/b through `square_to_ab` / `ab_to_square`). Its S is the stored picker x; the HSV readout derives S from sRGB bytes, so the two can differ.
- The color readout (`src/ui_egui/color_readout.rs`) shows `main_color_picker`'s `selected_color` (the same picker-space color as the readout) as Hex, sRGB, HSL, Oklab and OkLCh rows: monospace, fixed width and decimals so nothing shifts while dragging, `-` without a selection. The rows are rounded for display; a click copies `format_color_as`'s full precision. Each row is `interact_size.y` tall with no spacing between them (`color_readout_height`, counted in `fixed_height`).

### Theme
- `src/ui_egui/theme.rs` is the custom dark theme, set once in `startup()` (`theme::apply`, for both egui themes, so an OS theme switch keeps it). One accent (`ACCENT`) marks selection, hover, active widgets, slider fills and the tile resize line. Fills step canvas (central panel, gaps) < log drawer < pane cards < toolbar; `toolbar_frame` / `drawer_frame` frame the panels and `TileUi::pane_ui` draws each pane on a rounded card (`pane_card`, contents inset by its padding, never to a negative size: a tiny window can squeeze the tiles to nothing) with `PANE_GAP` between tiles.
- Text hierarchy: section headers (`section_header`, and `row_header`, which pads to a fixed width so the Points and Comb controls line up) are small muted uppercase; field labels use the noninteractive text color, values (widget text, readout values) the brighter inactive one. Tests find headers by their uppercase text.
- Spacing (`interact_size.y`, `item_spacing`, `button_padding`) feeds the hand-counted picker and previewer heights, so layout tests apply the theme (`lay_out_picker`, `draw_toolbar_and_tree`). Panel fills must stay dark: control point outlines and the ribbon halo contrast with the point's own color, not the panel (`markers_and_ribbon_stand_out_on_the_pane_and_canvas_fills`).

### 3D view
- `src/ui_egui/view_3d.rs`, shown by `Pane::View3d` above the previewer. `View3dPane::ui` clones the points, spline mode, picker and blend space and selection out of the context, `View3d::draw_ui` edits the copies, and the pane writes back the selection, and the points only when they changed, after `apply_control_point_constraints` (Clamp, Auto hue); auto comb runs in the picker's next `pre_draw_update`, where a point drag sets `dragging_index` and a handle drag `dragging_tangent`, like a square drag (only set, never cleared: the picker clears them). Lock, Window lock and Auto hue come in through `CurveSettings`. `View3dPane.ctx` is `#[serde(skip)]` (the saved tree carries no extra copy of the context; `startup` re-points it like the others). A restored tree without the tile simply has no 3D view.
- `gradient_linear_samples` takes `CURVE_SAMPLES` evenly spaced T from `Gradient::linear_at`, so the curve is the blended, gamut-mapped one the previewer shows; points sit at `HsvKeyValue::linear(picker_space)`.
- `View3dSpace::position` maps linear sRGB to world space, y up, within about [-0.5, 0.5]: centered cubes (x R, y G, z B), cylinders of radius 0.5 with hue 0 at +x turning counterclockwise seen from above, and unscaled Oklab `[a, L - 0.5, -b]`, so its hue turns the same way.
- `View3dSpace::linear_at` inverts `position` and clamps into the space: cube coordinates per axis, cylinder radius and height, Oklab by `map_into_srgb_gamut` (chroma reduced at the same L and hue). A 3D drag of a point or handle inside sRGB therefore stays inside. In OkLCh or Oklab without Clip, one outside sRGB is drawn gamut-mapped and moves by the target's offset from that drawn color at drag start (`picker_value_after_drag`), so it keeps its out-of-gamut chroma.
- Editing: `scene_items` holds the points and, in Bezier mode, the selected point's handles (not the first point's in-handle or the last point's out-handle), each marker at least `HANDLE_MIN_SCREEN_LENGTH` from its point (`handle_marker_pos`). A drag that presses within `HOVER_RADIUS` of one (`nearest`) moves it, else it orbits. `View3d.drag` (`ItemDrag`) snapshots every point (`start_points`), the item's drawn position and the press; each frame the drawn start position moves by the pointer's motion since the press on the camera-facing plane through it (`OrbitCamera::dragged_on_view_plane`), and `move_point_by_linear` / `move_handle_to_linear` store the `linear_at` color, computed from the snapshot alone: `linear_to_picker`, S/Y clamped, a gray keeps the start hue and a hue keeps its turn within half a turn of it (Oklab: z is L, clamped). So a held pointer changes nothing (the old per-frame version re-added the gap between an out-of-sRGB value and its gamut-mapped drawing every frame and ran off to the square's edge), and back at the press the item is bit for bit its start: a target that reads back as the start position keeps the start value, a handle gets its start tangent back. Lock too: `move_point_to` first puts every point's S/V and the dragged point's value back to the snapshot (the other points keep their current z, which the Auto hue constraint sets; tangents are not touched, so auto comb's handles stand), then moves the group from there. Under Auto hue (`CurveSettings::is_auto_hue`) a middle point instead keeps z bit for bit, since the constraints would snap it back: `auto_hue_drag_value` picks x/y whose drawn position lands nearest the pointer (`square_xy_nearest_on_screen`: `locally_nearest_on_screen`, damped Gauss-Newton with numeric derivatives plus an 8-direction pattern search that gets past kinks, the square's edges and gamut-mapped flats, runs from the start value; if it ends more than `SCREEN_FIT_ACCEPTED_PIXELS` off, a local minimum or a pointer off the sheet, it reruns from the points of a 9x9 grid over the square, nearest on screen first, until one lands or `SCREEN_FIT_SEEDS_SEARCHED` have run, and keeps the nearest; still a function of the pointer alone), then Lock and Clip apply as for any point drag (`move_point_to`). A moved point goes through `clip_points_to_srgb`; a handle goes through `drag_handle_to` (`CurveSettings::is_auto_comb_running`), so with Auto comb a drag along it sets its point's curvature. T never changes.
- Painted with `egui::Painter` only: `OrbitCamera::project` is a CPU perspective projection. Every segment, point and handle is sorted back to front by view depth each frame and faded with depth (`depth_fade`, across the depths of the space's gamut sphere, `OrbitCamera::scene_radius`); points and handle markers carry `POINT_DEPTH_BIAS` so they draw over their curve sample. Labels are painted last, unsorted.
- Gamut shading: `gamut_quads` subdivides the sRGB cube's faces mapped into the space (cubes, Oklab) or the cylinder's side and caps, with premultiplied vertex colors at `gamut_opacity` (0 paints nothing). A quad faces the camera when its normal, oriented away from mid gray, points at the eye. Back-facing quads are painted as one mesh before the sorted lines, points and handles, front-facing ones as one mesh after them, each sorted back to front.
- The space combo and the gamut opacity are persisted (serde defaults), the camera and the item drag are not (`#[serde(skip)]`): a viewpoint is one double-click from the default, and keeping it out of saved state means a camera change never breaks loading. The camera starts `None` and is fitted on first draw and on a double-click away from every item (`item_at`): `OrbitCamera::fitted` takes the default orientation and `refitted` the distance (`fitted_distance`), which puts the gamut's bounding sphere (`gamut_radius`, about the origin) at `FIT_FILL` of the pane's shorter side, and backs off further if a guide end or axis label would land outside `FIT_FILL` of a centered square of the shorter side at that orientation. Guides and labels reach past the sphere, so `orbited` refits the distance to the new orientation and keeps the zoom (distance over the fitted distance, exactly 1 until a scroll), clamped to `MIN_DISTANCE..MAX_DISTANCE`; the projection scales with the shorter side, so the aspect needs no term. Only Oklab's guides reach past its sphere, so its L label sits beside white (`OKLAB_L_LABEL_SIDE`) and its floor axes are short enough to leave the fit to the gamut at the default orientation. Switching the space (`View3d::set_space`) refits the distance and keeps the orientation.

### Misc
- The log filter defaults to `info,z_color_picker=debug` (`DEFAULT_LOG_FILTER` in `src/logger.rs`); a set `RUST_LOG` replaces it, e.g. `RUST_LOG=debug` shows dependency debug output too.
- `LogCollector` (`src/logger.rs`) captures log lines into a shared `Arc<Mutex<Vec<String>>>`, capped at 2000 lines, which the log drawer displays. Never call `log::*` while holding that mutex; `LogCollector::log` locks it too, so it would deadlock.
- The UI scale (`pixels_per_point`) is set in `startup()` to the current monitor's shorter side in physical pixels / 1080 (`ui_scale`), read from `ViewportInfo::monitor_size`. It is not persisted. If the size is unknown or unusable, it falls back to 2560x1440 (`HARDCODED_MONITOR_SIZE`), i.e. 1.33. The startup log line (`ui_scale_log_line`) gets the scale being set: `set_pixels_per_point` applies from the next pass, so `ctx.pixels_per_point()` would still read the old one.
- The debug windows live in `src/ui_egui/debug_windows.rs`.

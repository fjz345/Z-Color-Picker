# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Z-Color-Picker is a single-binary Rust (edition 2021) desktop app built on `eframe`/`egui` 0.31 + `egui_tiles`. The user places control points on a 2D saturation/value (or lightness) picker plus a hue bar, in a selectable picker space (HSV, HSL, OKHSV, OKHSL), and the app interpolates a color gradient through them using a selectable spline mode. Presets can be saved and loaded, and gradients or colors can be copied to the clipboard.

## Commands

```
cargo build
cargo run            # run from repo root: presets resolve relative to the CWD
cargo clippy         # exits 0; warn-level style lints remain
cargo test
cargo test hermite   # single test by name filter (bin crate; tests live in #[cfg(test)] modules under src/)
```

- The build is warning-free. Keep it that way: delete unused code, no `#[allow]`.
- Every `src` module has a `#[cfg(test)] mod tests`, except `debug_windows.rs`, `ui_common.rs` and the `mod` files. `preset.rs` tests use tempfile dirs, never `./presets`. Shared fixtures live in `#[cfg(test)] pub mod test_support` in `control_point.rs` (`point_with_tangent`, the runaway-tangent constants) and `hsv_key_value.rs` (`assert_close`). Widget tests run a headless `egui::Context::run`; the rest of the UI is checked by running the app.
- Line endings differ from file to file (some CRLF, some LF). Keep each file's existing endings.
- `.vscode/launch.json` has lldb (CodeLLDB) configs for the binary and its unit tests.
- The `accesskit` Cargo feature doesn't compile. The block it gates in `ZColorPicker::add_contents` is leftover code copied from egui's Slider.

## Controls (from README)
- Double-click (M1) on the picker: add a control point.
- Right-click (M2) on a point: remove it.
- Click the color readout or Ctrl+C: copy the selected point's color in the Copy-as format.
- Middle-click: copy the color under the cursor in the selected format. On the previewer, it copies the image instead.
- Drag (M1): move a point, a Bezier tangent handle, a hue gizmo, or a middle point's T (its marker on the T strip, or its previewer key band). End T markers and bands are fixed; clicking a marker selects its point.
- Inspector (H, S, V or L, T under the readout): drag, or click and type the selected point's value; Enter, Tab or a click away commits, Esc cancels.
- F12: debug window with the control point values.
- Esc: quit, only on a first press (not a key repeat) and only when `ZApp::is_input_blocked` is false: no widget had keyboard focus last frame, and no popup, modal (delete confirm, pending switch) or Create Preset window is open. It is read before the tree is drawn, because egui drops focus and closes popups during the Esc frame. The same flag blocks Ctrl+C (`should_quit_on_escape`, `is_copy_shortcut`).

## Architecture

### App state and ownership
- `src/main.rs` starts eframe. If eframe persistence storage holds a serialized `ZApp` (JSON under `eframe::APP_KEY`), the app is deserialized from it and `request_init()` sends it back through the startup path. Otherwise `ZApp::new` is used.
- `ZApp` (`src/ui_egui/app.rs`) is a small state machine (`Startup` -> `Idle` -> `Exit`). It owns the `egui_tiles::Tree<Pane>` and an `Rc<RefCell<ZColorPickerAppContext>>`.
- `ZColorPickerAppContext` is the central mutable state: `control_points`, `spline_mode`, `PresetHandler`, the picker and previewer widgets, pending input events, and so on. Each pane (`src/ui_egui/panes.rs`: ColorPicker, ColorPickerOptions, Previewer, Log) holds a clone of that `Rc`. After deserialization, `startup()` walks the tile tree and calls `update_ctx` to re-point every pane at the live context. Serde does not preserve `Rc` sharing, so this step is load-bearing.
- Because everything shares one `RefCell`, borrow conflicts are the main runtime hazard. The existing code clones data out, drops the borrow, draws, then re-borrows mutably to write back. Examples are the `ui()` methods in `panes.rs` and `show_create_preset_window`. Follow that pattern.
- Any cloned state has to be written back explicitly, or the edits are lost without any error. For example, `preset_bar_ui` has to assign `presets_window` and `preset_handler` back to the context.
- The toolbar (`ZApp::draw_toolbar`, a `TopBottomPanel` drawn before the tile tree) holds the preset bar (`WindowPreset` via `preset_bar_ui` in `panes.rs`), the Copy-as combo and the Log toggle; the options pane holds only the Points, Curve and Comb rows. The "Create Preset" window is drawn from `ZApp::draw_ui_tree` before the toolbar. Rename is a `popup_below_widget` popup, not a `menu_button`: egui menus are not `Memory` popups, so `any_popup_open` would miss them and Esc would also quit.
- The Log pane is hidden by default (`create_tree`). The Log toggle sets its tile's visibility (`Tree::set_visible`), which is saved with the tree (`Tiles.invisible`); state saved before that has an empty set, so the log shows until toggled once. The tile id is looked up every frame (`log_tile_id`); without a Log tile the toggle is not drawn.
- Fields marked `#[serde(skip)]` are transient UI/event state. Anything without it is persisted in eframe storage, so changing a persisted type's shape can break loading of existing saved state. On a parse failure, loading logs a warning (`Ignoring stored app state`) and falls back to defaults.

### Data model
- `ControlPoint` (`src/datatypes/control_point.rs`) is an enum over `ControlPointStorage { val, t, tangents: [Option<_>; 2] }`.
- `ControlPointValue` = `HsvKeyValue` (`src/datatypes/hsv_key_value.rs`), which stores `[f32; 3]`. The index order is **`[s (x), v (y), h]`, not `[h, s, v]`**: index 0/1 are the 2D picker position and index 2 is hue. In the HSL spaces y is lightness (see Color spaces). `HsvKeyValue` implements `splines::Interpolate`, with hue-aware lerp from `src/math.rs`.
- Tangents are stored as offsets relative to the point's value. Bezier keys, the ribbon, the comb and the drawn handles all use `bezier_handle` (point + offset with S/V clamped to the square, hue not), so a stored runaway tangent cannot wreck the curve.

### Spline evaluation
- `control_points_to_spline` (`src/ui_egui/control_points.rs`) converts control points into a `splines::Spline`, one match arm per `SplineMode` (`src/common.rs`). `SplineMode::ALL` feeds the Spline combo and the per-mode tests; a new mode goes there too.
- Keys are placed at `ControlPoint.t` ("T", the position along the gradient). Invariant (`has_valid_t`): first T = 0, last T = 1 (a single point has 0), strictly increasing by index, so index order is T order. `normalize_t` spaces invalid T evenly; it runs in `pre_draw_update` and `apply_control_point_constraints`, on preset load (`load_preset_from_disk`, in memory only) and on restored eframe state (`ZApp::init`, before `hold_auto_save_if_dirty`, so old data doesn't look dirty), each with a `log::warn`. `control_points_to_spline` keys invalid T evenly too (`key_ts`).
- Every T edit keeps the invariant, in `control_points.rs`: `insert_point` (between two points: the middle of their T; at an end: the new point is pinned and the others are squeezed by 1/old count), `remove_point` (removing an end rescales the rest onto 0..1), `mirror_t` (Flip), `drag_t` (middle points only, `MIN_T_GAP` from both neighbours). Auto hue interpolates middle hues by T.
- `HermiteBezier` is actually Catmull-Rom: the endpoints are duplicated as phantom keys, mirrored one neighbour spacing outside the end keys. Its tangents follow the T spacing (non-uniform Catmull-Rom in `HsvKeyValue::cubic_hermite`).
- There is no `Polynomial` mode; saved JSON that names it fails to parse.
- `flatten_control_points` unwraps hue across the 0/1 boundary before interpolation.
- `sample_spline_normalized` maps x in [0,1] onto the real keys (`real_keys` drops the Catmull-Rom phantoms), so x = T. It handles the end of a Catmull-Rom spline, where the `splines` sampler returns `None`. The ribbon (`generate_spline_points`) samples a fixed count per real segment between key T.
- The previewer (`src/ui_egui/previewer.rs`) gradient, quantized strip and key color bands all follow T, as does the picker's T strip gradient (`gradient_color_at`). Key color bands split halfway between neighbouring T (`key_band_edges`). The previewer edits its own copy of the points (band drag, Space evenly), and `PreviewerPane::ui` writes it back to the context when it changed.
- Curvature comb drawing lives in `src/ui_egui/curvature.rs` and has its own cubic evaluation. It is toggled via `ZColorPickerOptions::is_show_curvature_comb`; `curvature_comb_scale` multiplies every spike's length. Linear has no comb. Hermite segments are converted from the spline's Catmull-Rom keys to exact cubic Beziers (`catmull_rom_cubics`, the tangent formula of `HsvKeyValue::cubic_hermite`), so they follow the key times. Their inner control points are the read-only Hermite tangents drawn dashed on the selected point (`paint_auto_tangents`).
- Auto comb (`ZColorPickerOptions::is_auto_comb`, Bezier only) runs `apply_auto_comb` (`src/ui_egui/auto_comb.rs`) in `ZColorPickerWrapper::pre_draw_update`, after the constraints, so a later clamp can't move solved points. It keeps handle directions and solves only lengths, in S/V, from the endpoint-curvature equations of https://acko.net/blog/curvature-beziers/. An interior point's two handles are lined up; the handle dragged last frame (`dragging_tangent`) sets the line, so a drag turns a handle and its length is re-solved. Interior joints target the curvature of the circle through the point and its neighbours, end joints are free, and a segment with no solution keeps its lengths while its neighbours match it. Solved handles stay inside the square; tangent hue offsets are untouched. The result must be a fixed point (another pass changes nothing, bit for bit), or auto-save rewrites the preset every frame. `unsolved_joints` feeds the `N unsolved` label in the options.

### Presets
- `src/preset.rs`: one JSON file per `PresetEntity` in `./presets/` (the `presets/` folder is gitignored). The path comes from `std::env::current_dir()`.
- Presets are written through to disk: Create, Save, Rename and Delete in the preset bar (`WindowPreset::draw_content`, `ZApp::show_create_preset_window`) hit disk immediately via `PresetHandler`. Nothing is synced at exit.
- Every write goes to `<name>.json.tmp` and is renamed over the file (`fs::write_string_to_file`). Create and Rename refuse a name whose file already exists on disk (`ensure_no_preset_file`), even if it is not in the list; Rename allows a case-only change. Create writes the file, then adds it to the list. Rename uses `fs::rename`. Both re-sort the list in load order (`sort_presets`) and keep the selection on its preset. Delete removes the file first, behind a confirm `Modal`; a file that is already gone counts as deleted.
- Name rules, enforced by `validate_preset_name` / `PresetHandler::check_name`: not empty or whitespace; no `< > : " / \ | ? *` or control chars; no trailing dot or space; no reserved device name (CON, NUL, COM1..); at most 64 chars; no case-insensitive duplicate. The UI disables Create/Rename and shows the reason in red.
- When `auto_save_presets` is enabled, the selected preset is rewritten only when the current control points, spline mode or picker space differ from it (`PresetHandler::auto_save`), and only once no pointer button is held, so a drag writes once, on release. A failed write keeps the preset dirty, shows the error in the preset bar, and is not retried until the content changes again.
- `PresetHandler.presets` is `#[serde(skip)]`: presets are not in eframe storage, disk is the truth. At startup `init_presets` loads them from `presets_dir` (default `./presets`), skips non-`.json`, malformed or non-finite files (`first_non_finite_point`) with `log::warn`, and sorts them by name, case-insensitive. Only the selected preset's name is persisted (`selected_preset`); it is restored by case-insensitive name, else `None`. If the restored points differ from that file, `hold_auto_save_if_dirty` marks them as a held auto-save, so Auto-save does not overwrite the file until the next edit.
- Unsaved changes (`has_unsaved_changes`: the selection is dirty and Auto-save is off or its last write failed) show as `name *` in the combo. Picking a preset then, or while unselected points match no preset, sets `WindowPreset::pending_switch` and opens a modal instead of applying it: Save and switch / Discard / Cancel; for the already selected preset Save / Revert to saved / Cancel; with no selection Discard / Cancel. A failed save keeps the modal open with the error. Applying a preset clears the point selection.
- Save without a selection opens the Create Preset window.

### Color spaces
- `src/color_space.rs` holds flat conversions on `[f32; 3]` with linear sRGB as the hub: `srgb_to_linear` / `linear_to_srgb` (gamma sRGB, via ecolor), `linear_to_oklab` / `oklab_to_linear` and `oklab_to_oklch` (Ottosson's matrices, rounded to f32), `srgb_to_hsl`. Hue is in turns [0, 1) like the app's hue, `[h, s, l]` and `[l, c, h]` order; chroma below `ACHROMATIC_CHROMA` gets hue 0.
- `PickerSpace` (Hsv default, Hsl, Okhsv, Okhsl) says what a point's x/y mean; `picker_to_linear` / `linear_to_picker` convert `[h, s, v|l]`. `HsvKeyValue::color(space)` / `linear(space)` (S/V clamped, hue wrapped) is the only point or spline sample -> color path; the square, hue bar (s 1 at v 1, or l 0.5), T strip, ribbon, previewer, swatch and copy all go through it. A gray in any space reads back with s and h exactly 0.
- Hsv is ecolor's `HsvaGamma` (HSV over linear RGB with only V gamma-encoded, not CSS HSV), bit for bit; Hsl is CSS HSL over gamma sRGB. Okhsv/Okhsl port Ottosson's colorpicker code, except `compute_max_saturation`: green before red with a `BRANCH_TIE` margin and 3 Halley steps, because at sRGB blue both chords are 1, the reference's f32 tie picked the blue branch, and red's first zero lies before blue. With that, the primaries have s 1 (and OKHSV v 1). OkLCh is not a picker space (holes in its square).
- The space is persisted in `ZColorPickerAppContext.picker_space`, `AppDataCtx` (preset files) and `PreviewerData`, all `#[serde(default)]`, so older state and presets load as Hsv. The preset dirty check (`data_matches`) compares it; applying a preset applies its space. The Space combo (options Points row) changes it, and `ColorPickerOptionsPane::ui` then runs `convert_picker_space` once: each value and each Bezier handle (absolute, as `bezier_handle` builds it) goes through linear sRGB and is clamped into the cube; hue offsets keep their turns; a gray keeps its old hue. Float noise can move an 8-bit channel that sits on a rounding boundary (V 50%, 70%: x.5 / 255) by 1. Auto hue then re-interpolates middle hues in the new space, so middle colors change with it on.

### Clipboard / screen capture
Pressing the middle button stores a `ScreenshotTarget` in `pending_screenshot_target` and requests one `ViewportCommand::Screenshot`. It closes the copy popup first, because eframe captures the frame painted in that same update. The target is the previewer rect under the cursor (rects come from `stored_ui_responses`), or else the pixel under the cursor. The screenshot event arrives in a later frame. `handle_screenshot_event` crops it with `crop_screenshot` (`src/ui_egui/clipboard.rs`) and turns it into a `ClipboardCopyEvent`. A pixel target takes the physical pixel at `floor(cursor * ppp)`, clamped to the screenshot; a previewer crop rounds both edges, so it takes the pixels whose centres lie inside the rect, clamped too. That event is consumed at the start of the next `Idle` frame (`handle_clipboardcopy_event`). Nothing in the app requests that frame: egui repaints right after any pass whose input has events, and the Screenshot event counts. A single pixel is copied as text in `color_copy_format`; a larger region is copied as an image via `arboard`. A failed write shows `Copy failed: <error>` in the popup.
- `format_color_as` supports all 14 `ColorStringCopy` formats, from unmultiplied sRGB; `RGB`/`RGBA` are linear. `HSL`/`OKLAB`/`OKLCH` are CSS Color 4 strings without alpha, with the fewest decimals that map every 8-bit color back to itself (checked over all 16.7M); `css_number` trims trailing zeros.
- A readout click or Ctrl+C skips the screenshot: `selected_color_payload` formats the selected point and `write_payload_to_clipboard` (shared with middle-click) writes it. Ctrl+C is left to egui while input is blocked (`is_input_blocked`, see Controls) or label text is selected.

### Picker layout and inspector
- `picker_ui`'s `fixed_height` hand-counts `main_color_picker`'s stack (swatch, readout, inspector, hue strip, T strip, square, overlay spacing). A new row must update it; `picker_insets_square_in_height_limited_pane` fails otherwise.
- The point inspector (`src/ui_egui/inspector.rs`) edits `MainColorPickerCtx.control_points`, the clone that `ColorPickerPane::ui` writes back after `post_draw` applies the constraints; it never touches the app context. Each DragValue edits a local copy and writes only on `changed()`, with `clamp_existing_to_range(false)` and `update_while_editing(false)`: drawing never rewrites a point (auto-save compares bit for bit), and typing commits once instead of per keystroke. The row's id includes the selected index, because a DragValue applies its pending text on focus loss to whatever value it is bound to. S/V under Lock go through `limit_group_delta` / `apply_group_delta_sv` like a square drag, T through `drag_t` / `t_drag_bounds`, H keeps the turn like `hue_after_drag`. Its S is the stored picker x; the HSV readout derives S from sRGB bytes, so the two can differ.

### Misc
- The log filter defaults to `info,z_color_picker=debug` (`DEFAULT_LOG_FILTER` in `src/logger.rs`); a set `RUST_LOG` replaces it, e.g. `RUST_LOG=debug` shows dependency debug output too.
- `LogCollector` (`src/logger.rs`) captures log lines into a shared `Arc<Mutex<Vec<String>>>`, capped at 2000 lines, which the Log pane displays. Never call `log::*` while holding that mutex; `LogCollector::log` locks it too, so it would deadlock.
- The UI scale (`pixels_per_point`) is set in `startup()` to the current monitor's shorter side in physical pixels / 1080 (`ui_scale`), read from `ViewportInfo::monitor_size`. It is not persisted. If the size is unknown or unusable, it falls back to 2560x1440 (`HARDCODED_MONITOR_SIZE`), i.e. 1.33.
- The debug windows live in `src/ui_egui/debug_windows.rs`.
